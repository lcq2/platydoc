Subsequent batches add Skywalk control/readiness, memory/packets, namespace/lookup, routes/datapaths, netif/FQ-CoDel and ACL mechanisms. The [packet/filter batch](first-release-expansion.md#12-packet-transformations-filtering-ipc-internals-and-logging) explains selected reassembly/tracking, aggregation/segmentation, offload rollback, filters/reinjection and agents/traffic rules. New companions trace [NECP policy evaluation](../subsystems/networking/necp-policy-evaluation.md), [NECP clients and flow registration](../subsystems/networking/necp-clients-and-flow-registration.md) and [socket content filtering](../subsystems/networking/socket-content-filtering.md). The [TCP recovery companion](../subsystems/networking/tcp-loss-recovery-and-congestion-control.md) now traces selected SACK/RACK, retransmission and congestion decisions, while [Skywalk user/kernel pipes](../subsystems/networking/skywalk-user-and-kernel-pipes.md) covers paired-ring transfer and provider callback transports. The [diagnostics companion](../subsystems/networking/skywalk-diagnostics-configuration-and-tests.md) now connects selected Skywalk exporters, counter lifetimes, guard/failure reporting, configuration and local tests. The dispositions below are historical; remaining congestion/option combinations, unreviewed diagnostic/test cases, transport overlays, deeper PF/IPsec state and policy/provider combinations still need expansion.

[Coverage audit](../coverage-audit.md) · [Coverage and verification](../coverage.md) · [Earlier expansion record](../expansion-audit.md)

This is an expansion backlog for the checked-out XNU source, not a new implementation guide. It inventories **all 34 Markdown files** in the three assigned directories: 10 process chapters, 15 VFS chapters, and 9 networking chapters, including their READMEs. It compares the explanations already present with selected source bodies, interfaces, configuration switches, and local tests. No technical chapter or kernel source was changed for this audit.

The strongest existing coverage follows ownership through process transitions, signal delivery, workqueues, knotes, vnode identity and reclamation, cached file I/O, buffer completion, socket I/O, TCP connection lifetime, and selected Skywalk channel/flow paths. The main remaining work is to explain adjacent facilities and the decisions inside protocols that are currently navigation entries or short summaries. The recent file-cache, buffer-cache, vnode-reuse, and signature chapters should remain the foundation; repeating those traces would add less value than the candidates below.

**Skywalk is explicitly a full-surface P1 expansion program.** Its two existing chapters are useful, but the requested backlog now covers every source area under `bsd/skywalk`, its local userspace wrappers, configuration, and tests. This is broader than filling a few omissions in those chapters.

## How to read the dispositions and priorities

- **Retain:** the chapter fulfills its present role. This does not mean every source branch or related interface has been documented.
- **Deepen:** the chapter's central subject still has important unexplained mechanisms; expansion may be split into neighboring chapters to preserve readability.
- **Add-neighbor:** retain the existing trace and add a separate treatment of an adjacent facility.
- **P1:** foundational work, or the explicitly requested complete Skywalk program.
- **P2:** useful implementation depth after the foundations.
- **P3:** specialized protocol, policy, or configuration work with narrower readership or more external dependencies.

The audit checked chapter content and stated limits, then read selected bodies to establish that proposed questions correspond to actual local code. It did not re-prove every existing sentence, reconstruct every branch in the cited files, execute the tests, or build a kernel. A file citation is evidence for a particular claim, not a claim of whole-file analysis. Source-file or line totals cannot establish semantic coverage.

## Prioritized expansion candidates

### A1 — P1: descriptor reservation, duplication, close, and cross-interface ownership

**Current coverage:** [descriptors](../subsystems/processes/descriptors-ipc.md), [socket ownership](../subsystems/networking/socket-lifecycle-and-io.md), and [AIO cleanup](../subsystems/processes/async-io.md).

**Evidence:** [`finishdup`](../../xnu/bsd/kern/kern_descrip.c#L555) verifies the old slot, retains its `fileglob`, drops the fd lock to allocate a new `fileproc`, then publishes into a reserved slot. [`dup2`](../../xnu/bsd/kern/kern_descrip.c#L2529) handles an already-reserved target by waiting/restarting and closes a populated target with the reservation-preserving mode before completion. [`fp_close_and_unlock`](../../xnu/bsd/kern/kern_descrip.c#L1727), [`guarded_close_np`](../../xnu/bsd/kern/kern_guarded.c#L423), and [`fileport_makeport`](../../xnu/bsd/kern/kern_descrip.c#L6066) establish related but different entry points.

**Proposed sections/questions:**

1. `filedesc` slot states, `fileproc` I/O references, and shared `fileglob` state: which fields belong to the descriptor versus the open file?
2. Allocation, reservation, publication, and failure rollback; what can another thread observe while allocation sleeps?
3. `dup`, `dup2`, close-on-exec/fork flags, guarded descriptors, and concurrent close/reuse. Why is target close in `dup2` not equivalent to a separately issued `close`?
4. File-operation dispatch, descriptor lookup/drain, final close, and fileport conversion. Distinguish allocation rollback from closing a previously published fd.

**Benefit/dependencies/limits:** this supplies the missing foundation for A2, A3, A5, and Skywalk's guarded descriptors. Link existing AIO/exec teardown instead of rewriting it. The relevant kernel implementation is local; libc wrappers and application-level assumptions must be identified separately. Local regression routes include [guarded fds](../../xnu/tests/fd_guarded.c), [fd limits](../../xnu/tests/fd_table_limits.c), and the [failed receive/record-lock preservation test](../../xnu/tests/fd_recvmsg_fail_file_lock_168227949.c#L160). The latter explicitly acquires a lock, forces descriptor receive failure, and checks that the original lock remains held; it is a useful cross-facility failure example.

### A2 — P1: anonymous pipes and UNIX-domain data/rights lifetime

**Current coverage:** [descriptor/local IPC overview](../subsystems/processes/descriptors-ipc.md), [socket ancillary ownership](../subsystems/networking/socket-lifecycle-and-io.md), and the already detailed [FIFO chapter](../subsystems/vfs/device-nodes-and-fifos.md).

**Evidence:** [`pipe_write`](../../xnu/bsd/kern/sys_pipe.c#L911) must recheck room after acquiring the pipe I/O lock; its [space/atomic-write branch](../../xnu/bsd/kern/sys_pipe.c#L960) treats writes up to `PIPE_BUF` differently and checks close/drain state. [`uipc_rcvd`](../../xnu/bsd/kern/uipc_usrreq.c#L427) restores the stream sender's buffer allowance from receiver consumption and wakes writers. [`unp_gc`](../../xnu/bsd/kern/uipc_usrreq.c#L2556) distinguishes references carried in messages from external roots, marks/defer-scans fileglobs, and must restart when socket locking cannot safely proceed. These are not explained by the existing internalize/externalize summary.

**Proposed sections/questions:** pipe pair allocation and endpoint closure; read/write sleep and interruption; atomic versus partial writes; select/knote thresholds; UNIX stream/datagram connect and disconnect; receiver-driven backpressure; control-message truncation/peek/failure; `SCM_RIGHTS` references from descriptor reservation through externalization; cyclic UNIX-socket rights collection and races with ordinary close.

**Benefit/dependencies/limits:** A1 establishes fd ownership; the current socket and kqueue chapters establish generic locks and filters. Preserve FIFO's separate pathname/open lifecycle. The kernel mechanisms are local. [Pipe drain](../../xnu/tests/pipe_drain.c), [SCM peek](../../xnu/tests/unp_scm_rights_peek.c), and [SCM pointer-disclosure regression](../../xnu/tests/scm_rights_leak.c) are useful reading routes, but peek tests alone do not validate the whole cyclic collector.

### A3 — P1 foundation, P2 extensions: user-address waits, POSIX named IPC, and SysV cleanup

**Current coverage:** [pthread/workqueue boundary](../subsystems/processes/pthread-workqueue-lifecycle.md) and [local IPC navigation](../subsystems/processes/descriptors-ipc.md). Workqueue servicing is already deep; user-address synchronization is a different missing mechanism.

**Evidence:** [`sys_ulock_wait2`](../../xnu/bsd/kern/sys_ulock.c#L519) selects operation forms; its [compare/owner/turnstile path](../../xnu/bsd/kern/sys_ulock.c#L645) performs a no-fault atomic value read under protection, checks the expected value, manages owner-thread references, and prepares the turnstile before waiting. [`sem_wait`](../../xnu/bsd/kern/posix_sem.c#L981) combines a typed fd reference and POSIX-semaphore protection with the Mach semaphore call and error translation. [`pshm_unlink`](../../xnu/bsd/kern/posix_shm.c#L1017) and [final dereference](../../xnu/bsd/kern/posix_shm.c#L1093) separate name removal from release of memory-entry-backed storage. [`semexit`](../../xnu/bsd/kern/sysv_sem.c#L1321) walks per-process undo state.

**Proposed split:** first a user-lock chapter covering keys, expected-value races, owner/turnstile donation, wake targeting, timeout/interruption, and reference cleanup. Then a named-IPC chapter covering semaphore namespace/object/fd states and shared-memory name/descriptor/mapping lifetime. A SysV companion should trace permission and ID lookup, `IPC_RMID`, blocked sender/receiver/semaphore operations, shared-memory attachments, and `SEM_UNDO` on exit. Do not present these APIs as interchangeable wrappers.

**Benefit/dependencies/limits:** closes a major process-to-VM/runtime gap; depends on A1 and existing turnstile/Mach semaphore guides. `SYSV_SEM`, `SYSV_MSG`, and `SYSV_SHM` are [separate configuration options](../../xnu/config/MASTER#L76), and their [syscall declarations are conditional](../../xnu/bsd/kern/syscalls.master#L365). Pthread library algorithms remain external even though ulock entry points are local. Tests include [ulock timeout/wake](../../xnu/tests/ulock.c), [POSIX semaphores](../../xnu/tests/posix_sem.c), [POSIX shared memory](../../xnu/tests/testposixshm.c), and [SysV message control races](../../xnu/tests/sysv_msgctl_race.c); their assertions are selected regressions, not a specification of every API branch.

### A4 — P2: TTY/PTTY state, sessions, and job-control signals

**Current coverage:** [device dispatch](../subsystems/vfs/device-nodes-and-fifos.md), [process transitions](../subsystems/processes/process-transitions.md), and [signal delivery](../subsystems/processes/signal-delivery-and-return.md) expose the boundaries but not terminal behavior.

**Evidence:** [`ttread`](../../xnu/bsd/kern/tty.c#L2100) has [background-process-group checks](../../xnu/bsd/kern/tty.c#L2130) that can return `EIO`, send `SIGTTIN`, or return after interruption, before canonical/raw queue handling. [`ttioctl`](../../xnu/bsd/kern/tty.c#L1062) has a separate control path; [`ptmx_clone`](../../xnu/bsd/kern/tty_ptmx.c#L475), [PTY filter processing](../../xnu/bsd/kern/tty_ptmx.c#L903), [`setsid_internal`](../../xnu/bsd/kern/kern_prot.c#L487), and [`setpgid`](../../xnu/bsd/kern/kern_prot.c#L574) connect device state to process/session ownership.

**Proposed sections/questions:** PTY master/slave creation and devfs identity; `tty` queues and line discipline; canonical input and raw `VMIN`/`VTIME`; output flow control; controlling terminal, session, foreground group and orphan-group rules; `SIGTTIN`/`SIGTTOU` and hangup/revoke; readiness and close-time wakeups.

**Benefit/dependencies/limits:** explains a familiar interface whose behavior cannot be inferred from generic reads or signal frames. Reuse the signal guide; do not repeat ARM64 delivery. Process personas and diagnostic/core-dump work belong to the [security/development audit](security-and-development.md). The local TTY/PTY core can be traced; individual external serial/USB drivers cannot. [TTY ioctls](../../xnu/tests/tty_ioctl.c), [TTY hang regression](../../xnu/tests/tty_hang.c), and [PTY kevents](../../xnu/tests/kevent_pty.c) provide bounded scenarios.

### A5 — P2: advisory range locks, leases, and descriptor-related release

**Current coverage:** [open-file objects](../subsystems/vfs/vnodes-mounts-and-dispatch.md), [namespace mutation](../subsystems/vfs/namespace-mutations.md), and [descriptor overview](../subsystems/processes/descriptors-ipc.md).

**Evidence:** [`lf_advlock`](../../xnu/bsd/kern/kern_lockf.c#L203) normalizes file-relative ranges and selects operations over `v_lockf`; [`lf_setlock`](../../xnu/bsd/kern/kern_lockf.c#L522) includes a [POSIX deadlock walk](../../xnu/bsd/kern/kern_lockf.c#L565) distinct from OFD/flock owners and drops locks/retries when it cannot safely acquire another vnode's lock. [`vnode_setlease`](../../xnu/bsd/vfs/vfs_subr.c#L12990) and [`vnode_breaklease`](../../xnu/bsd/vfs/vfs_subr.c#L13223) implement a different protocol: conflict notification, release/downgrade state, nonblocking errors, and waiting.

**Proposed sections/questions:** compare process, open-file-description and flock ownership; range insertion/splitting/merging/unlock; blocked requests, interruption, deadlock detection; duplicate descriptors and close effects; failed `SCM_RIGHTS` receive versus a real close; read/write lease conflicts, NOTE notifications, deadlines/acknowledgments, and dataless/namespace-operation interactions.

**Benefit/dependencies/limits:** makes A1/A2 lifetime rules concrete and explains why a successful operation may depend on another process releasing state. Leases are guarded by [`CONFIG_FILE_LEASES`](../../xnu/config/MASTER#L144). Local lock/lease mechanisms are available; remote lock-manager behavior should be linked to existing NFS limits. Tests include [record locks](../../xnu/tests/lockf_basic.c), [lease notifications and acknowledgments](../../xnu/tests/file_leases.c), and A1's failed-receive regression.

### A6 — P2: metadata access, permission evaluation, and filesystem event queues

**Current coverage:** [pathname/authorization](../subsystems/vfs/pathname-and-authorization.md), [namespace mutation](../subsystems/vfs/namespace-mutations.md), [credential-specific vnode auth cache](../subsystems/vfs/vnode-cache-identity-and-reuse.md), and [generic knote lifetime](../subsystems/processes/kqueue-and-workloops.md). Cache validity is already well covered; authorization decisions and event consumers are not the same subject.

**Evidence:** [`setxattr`](../../xnu/bsd/vfs/vfs_syscalls.c#L13986) checks flags/protected names, chooses lookup rules, may break a parent lease, constructs the `uio`, calls `vn_setxattr`, and posts an event after success. [`setattrlist_internal`](../../xnu/bsd/vfs/vfs_attrlist.c#L4526) validates attribute bitmaps and packed input. [`vnode_authorize_simple`](../../xnu/bsd/vfs/vfs_subr.c#L9673) is a concrete permission-evaluation starting point. [`add_fsevent`](../../xnu/bsd/vfs/vfs_fsevents.c#L377) filters/coalesces work; the [watcher enqueue path](../../xnu/bsd/vfs/vfs_fsevents.c#L1535) holds event references and records drops or clears a lagging client's queue.

**Proposed sections/questions:** xattr syscall/VNOP/default implementation boundaries, protected attributes and failed copyin; attrlist bitmaps, length/offset packing and partial results; POSIX/ACL allowed/denied action evaluation and inheritance boundaries; what invalidates cached authorization; vnode NOTE producers versus `/dev/fsevents` consumers; watcher admission, coalescing, references, queue overflow, dropped-event recovery, and close.

**Benefit/dependencies/limits:** connects successful mutations to observable notifications and permission changes. Depends on A5 for leases and existing vnode/kqueue references. `CONFIG_FSE` is [explicit](../../xnu/config/MASTER#L104). APFS on-disk xattr/ACL storage and userspace FSEvents persistence/replay are external boundaries, not missing kernel algorithms to invent. Local tests such as [full-path attrlist](../../xnu/tests/vfs/getattrlist_fullpath.c) cover selected layouts; a future chapter should inventory attribute/event regressions before claiming exhaustive test support.

### A7 — P1: UDP and IPv6 socket-to-packet traces

**Current coverage:** [TCP/IP overview](../subsystems/networking/tcp-ip-interfaces.md) ends with UDP/IPv6 reading branches; [socket I/O](../subsystems/networking/socket-lifecycle-and-io.md) supplies generic ownership but not protocol decisions.

**Evidence:** [`udp_send`](../../xnu/bsd/netinet/udp_usrreq.c#L2688) has PCB/error cleanup and flow-divert/NECP decisions before ordinary output. [`udp_input`](../../xnu/bsd/netinet/udp_usrreq.c#L351) checks lengths/checksums and has multicast/broadcast PCB fanout. [`udp6_send`](../../xnu/bsd/netinet6/udp6_usrreq.c#L1213) handles address-family validation, content-filter-saved destination context, and mapped-IPv4 cases. [`udp6_output`](../../xnu/bsd/netinet6/udp6_output.c#L154) has interface restrictions, feedback, source/scope selection, and per-packet option handling.

**Proposed sections/questions:** bind/connect/disconnect and PCB tuple publication; unconnected send and per-message source/interface options; IPv4-mapped addresses and `IPV6_V6ONLY`; source/scope selection and route lifetime; zero-length datagrams; checksum, receive demultiplexing and multicast fanout; ancillary metadata, asynchronous ICMP errors, and send/receive queue failures.

**Benefit/dependencies/limits:** supplies the other widely used transport family and a real IPv6 path. Reuse socket/mbuf ownership, and keep A8 neighbor/reassembly algorithms separate. The kernel paths are local; DNS resolution and applications' user transports are not. [UDP disconnect](../../xnu/tests/udp_disconnect.c), [zero-byte UDP readiness](../../xnu/tests/socket_0byte_udp_poll_58140856.c), and [mapped-v6 fragmentation options](../../xnu/tests/v4mappedv6_dontfrag.c) are useful API scenarios rather than proof of all protocol branches.

### A8 — P2: IP control paths, neighbor resolution, fragments, and multicast membership

**Current coverage:** [packet/route/interface lifetime](../subsystems/networking/packets-routes-and-interfaces.md) explains route references and interface attachment, not all ARP/NDP or reassembly state.

**Evidence:** [`arp_lookup_ip`](../../xnu/bsd/netinet/in_arp.c#L1282) validates interface/address state, resolves a route/gateway under references, and handles broadcast/multicast or missing neighbor state. [`nd6_output`](../../xnu/bsd/netinet6/nd6.c#L3911) performs its own gateway-route and neighbor handling. [`ip_reass`](../../xnu/bsd/netinet/ip_input.c#L1844), [`frag6_input`](../../xnu/bsd/netinet6/frag6.c#L278), [`igmp_input`](../../xnu/bsd/netinet/igmp.c#L1657), and [`mld_input`](../../xnu/bsd/netinet6/mld6.c#L1554) identify distinct state machines currently reached only by navigation.

**Proposed split:** route mutation and route-socket notification, then ARP/NDP address/neighbor state, pending packet ownership, retries and detach; IPv4/IPv6 fragment validation, queue keys, overlap/limit/time expiry, assembly and failure frees; multicast socket membership to IGMP/MLD reporting and interface teardown. Explain ICMP error generation/consumption at the relevant transitions, rather than attempting a catalogue of all ICMP messages.

**Benefit/dependencies/limits:** explains why output can be accepted yet wait for link resolution, or input can be retained without becoming a datagram. A7 provides endpoints; existing route/reference and interface-detach guides provide lifetimes. Hardware address resolution callbacks and external routers remain explicit boundaries. [Neighbor lookup](../../xnu/tests/net/nd6lookup.c), [IPv6 fragment regression](../../xnu/tests/net/ip6_frag_hbh_panic.c), and [fragmented ICMP payload](../../xnu/tests/icmp_fragmented_payload.c) are selected evidence routes, not full protocol-conformance tests.

### A9 — P2: TCP loss recovery and congestion-control decisions

**Current coverage:** [TCP connections/timers](../subsystems/networking/tcp-connections-and-timers.md) already covers connection/accept/close and timer lifetime; no repeat handshake chapter is needed.

**Evidence:** the [algorithm table](../../xnu/bsd/netinet/tcp_cc.c#L61) includes NewReno, LEDBAT, CUBIC, and Prague. [`tcp_rack_detect_loss` and timer arming](../../xnu/bsd/netinet/tcp_rack.c#L244) scans transmit ordering, computes remaining time, and modifies reordering/probe timers. [`tcp_sack_doack`](../../xnu/bsd/netinet/tcp_sack.c#L416) and [CUBIC ACK handling](../../xnu/bsd/netinet/tcp_cubic.c#L323) provide concrete missing algorithm bodies.

**Proposed sections/questions:** ACK/SACK state versus socket-buffer release; hole/scoreboard allocation and exhaustion; RACK transmission ordering and reordering window; TLP/PTO versus RTO; entering/leaving recovery; per-algorithm state, initialization, ACK/loss callbacks and congestion-window changes; ECN/Prague integration and configuration. Include one traced loss/recovery sequence, distinguishing elapsed-time checks from scheduled timer ownership.

**Benefit/dependencies/limits:** extends an already good control-flow foundation into actual transport decisions. Do not infer current behavior from a textbook TCP description or equate Skywalk flow tracking with a BSD `tcpcb`. Algorithm implementations are local; real performance requires runtime/network experiments. Existing TCP information, keepalive, TFO and socket-option tests are useful API regressions, but this audit did not establish a complete numerical congestion-control oracle.

### A10 — P2: NECP clients and content-filter control/data coordination; P3 transport overlays

**Current coverage:** [policy extensions](../subsystems/networking/policy-extensions.md) names hooks; [Skywalk lifecycles](../subsystems/networking/skywalk-lifecycles.md) traces one netagent-to-flow installation.

**Evidence:** [`necp_client_action`](../../xnu/bsd/net/necp_client.c#L12395) dispatches add/claim/remove/copy/update/flow/agent operations after typed-fd and MAC checks. [`necp_client_add`](../../xnu/bsd/net/necp_client.c#L8199), [`necp_client_remove`](../../xnu/bsd/net/necp_client.c#L8578), and [`necp_client_add_flow`](../../xnu/bsd/net/necp_client.c#L9965) define deeper reading routes. [`cfil_ctl_send`](../../xnu/bsd/net/content_filter.c#L1920) validates control messages before processing pass/drop/bless and other operations; [`cfil_service_inject_queue`](../../xnu/bsd/net/content_filter.c#L4447) and [`cfil_service_pending_queue`](../../xnu/bsd/net/content_filter.c#L4615) expose distinct retained-data stages.

**Proposed sections/questions:** NECP fd/client/flow-registration identities, locks and result generations; policy evaluation and asynchronous update visibility; agent assertions and nexus requests; socket lifetime versus client lifetime; filter attachment and control protocol; byte offsets, pass/peek watermarks, queue movement, reinjection, disconnect and process exit; exactly when an mbuf is consumed or retained on error. Add separately bounded flow-divert and MPTCP sections for control connection/subflow creation, scheduling, retransmission mapping and close; their current summaries do not establish those mechanisms.

**Benefit/dependencies/limits:** connects sockets to policy and A12 without pretending a hook call explains the policy engine. NECP, content filtering, flow diversion and MPTCP have [configuration switches](../../xnu/config/MASTER#L75). Kernel structures/control handlers are available; userspace agents, Network Extension policy production, and peer behavior are not. Any future test plan should distinguish in-tree control API regressions from tests requiring privileged external agents.

### A11 — P3: PF and IPsec rule/state/security-association lifetime

**Current coverage:** [policy extensions](../subsystems/networking/policy-extensions.md) describes packet hook placement and ownership only.

**Evidence:** [`pf_test`](../../xnu/bsd/net/pf.c#L9714) requires PF protection, checks enabled/generated/skip/interface conditions, and can normalize or drop the packet before rule/state decisions. [`pf_test_rule`](../../xnu/bsd/net/pf.c#L4926), [`pf_test_state_tcp`](../../xnu/bsd/net/pf.c#L7016), and [`pf_test_state_udp`](../../xnu/bsd/net/pf.c#L7622) are separate branches. [`ipsec4_output`](../../xnu/bsd/netinet6/ipsec.c#L3670) builds request indices, follows SA requests, and handles a missing association; its policy/SA selection is not an explanation of cryptographic transforms.

**Proposed sections/questions:** rule/control publication and packet lookup; state keys, NAT rewrites, checksums, timeouts and purge; packet representation/consumption on normalization or error; SPD versus SAD, policy/SA references and acquisition; transport/tunnel processing and nested requests; inbound validation, replay windows, transform callback boundaries and teardown. BPF capture/filter programs are a separate observer facility and must not be presented as PF implementation.

**Benefit/dependencies/limits:** specialized but important packet-policy depth; depends on mbuf/IP ownership and A8. PF and [IPsec/ESP options](../../xnu/config/MASTER#L164) must be distinguished from a particular running configuration. Local C establishes kernel control/data contracts; external key-management daemons and cryptographic primitive internals require their own sources. [IPsec tests](../../xnu/tests/ipsec.m) and the [SA-count overflow regression](../../xnu/tests/net/ipsec_sav_count_overflow.c) are useful bounded routes. No claim of a complete PF/IPsec test audit is made.

### Existing strengths and why the program is larger

[Skywalk](../subsystems/networking/skywalk.md) already traces TX sync validation, a copied user-pool-to-device-pool flowswitch transmit path, receive dispatch, and the external netif provider boundary. [Skywalk lifecycles](../subsystems/networking/skywalk-lifecycles.md) adds channel binding, user-allocation hashes, allocation/free rings, detached RX ownership, channel close, flow installation rollback, table/reference removal, and linger.

Those guides should be retained and reused. They do **not** constitute coverage of every nexus type, control ABI, event/readiness path, metadata contract, arena/cache implementation, namespace reservation, classifier/route/reassembly algorithm, logical-link queue, filtering mode, statistics interface, or error/teardown permutation. The following is an inventory and proposed chapter split for the **whole local surface**, including mechanisms that already have an introductory trace.

### Decisive source checks supporting this split

These are targeted body checks establishing the need for the expansion, not substitutes for its eventual research:

- [`nxctl_close`](../../xnu/bsd/skywalk/nexus/nexus.c#L229) removes fd/attached ownership, closes only providers owned by that controller, and restarts provider traversal because nested work can drop global Skywalk protection. A one-line “controller closes providers” description would omit the synchronization mechanism.
- [`ch_kqfilter`](../../xnu/bsd/skywalk/channel/channel.c#L1060) validates adapter admissibility, selects three distinct filter implementations, stores the channel hook, and attaches under channel protection. Generic socket readiness is not sufficient documentation of this API.
- [`skmem_arena_mmap`](../../xnu/bsd/skywalk/mem/skmem_arena.c#L1497) checks active/nondefunct state, creates an IOKit mapper, retains the arena, records mapping membership, and unwinds failures. [`skmem_arena_defunct`](../../xnu/bsd/skywalk/mem/skmem_arena.c#L1718) returns `EBUSY` for an active arena before reaping caches and tearing down eligible regions. Defunct, inactive, unmapped and freed must therefore be separate documented states.
- [`nx_netif_llink_add`](../../xnu/bsd/skywalk/nexus/netif/nx_netif_llink.c#L444) checks ID uniqueness under the logical-link lock, initializes external queues after releasing it, and destroys the new link on failure; success establishes an additional reference. Local link creation is not proof of provider queue initialization success.
- [`nx_netif_filter_inject`](../../xnu/bsd/skywalk/nexus/netif/nx_netif_filter.c#L80) takes filter references under a mutex and frees incoming packet chains on disabled/removed-filter paths. Filters must be documented as packet owners, including races, rather than merely callbacks.
- [`protons_reserve_locked`](../../xnu/bsd/skywalk/namespace/protons.c#L171) has process/effective-process identity and existing-token rules distinct from address/port namespace reservation. The namespace directory contains multiple kinds of identity.
- [`fq_codel_enq`](../../xnu/bsd/net/classq/classq_fq_codel.c#L901) distinguishes mbuf and Skywalk packet representations, uses packet timestamps and flow/service metadata, and has a memory-failure drop result. Queue scheduling crosses the Skywalk directory boundary and needs its own ownership/error trace.

### Tests, configuration, external limits, and completion criteria

The [syscall table](../../xnu/bsd/kern/syscalls.master#L792) exposes nexus operations 503–509 and channel operations 510–514. [`SKYWALK` and the four `CONFIG_NEXUS_*` options](../../xnu/config/MASTER#L85) are separate build decisions; feature eligibility, interface mode and runtime capabilities add more conditions. Their presence in source does not establish that a specific product build enables every path.

The local test directory includes binding, full/one-slot/ring-ID operations, kqueue close, bad-ring input, shutdown/teardown, flow lookup and namespace reservation, steering, netif direct/compat, filter, reassembly, restricted ports, and multiprocess exercises. Particularly useful concrete checks are [read-only schema/malformed-ring tests](../../xnu/tests/skywalk/skt_writemem.c#L43): one expects an exception after writing read-only channel information, while another corrupts ring descriptors and checks sync failure. The [memory harness](../../xnu/tests/skywalk/skt_memory.c#L42) explicitly relies on external panic/hang detection; its empty main function must not be counted as a standalone allocator correctness proof. Other files, such as [reassembly](../../xnu/tests/skywalk/skt_reass.c), [teardown](../../xnu/tests/skywalk/skt_teardown.c), [flow lookup](../../xnu/tests/skywalk/skt_flowlookup.c), and [filter](../../xnu/tests/skywalk/skt_filter.c), are identified for the next research pass, not claimed here as completely reviewed or executed.

Most listed control, memory, ring, packet, classifier, namespace and queue machinery is implemented locally. Actual hardware providers, NIC/firmware behavior, AOP/offload services, and userspace transport/policy implementations have external portions. The guide can explain registration structures, arguments, capability checks, ownership before/after callbacks, and local failure handling; it must not infer unavailable implementations behind those callbacks. DMA/memory-mapping details should reuse the [driver memory guide](../subsystems/drivers/memory-descriptors-and-cpu-mappings.md) and its DMA neighbors when crossing into IOKit.

For each proposed chapter, completion should require an interface inventory with source symbol and configuration, input/output ownership, synchronization and blocking context, one normal path, one meaningful failure/teardown path, cross-links to the owning layer, and tests or an explicit untested/external boundary. For the full program, reconcile that inventory against every source-directory row above, the kernel/user API headers, syscall table, provider callback tables, and test families. This is a measurable research checklist; it is not a promise that documentation can exhaust every branch combination.

## Order of work and residual limits

The first independent work packages are A1/A2, A7, and the P1 Skywalk program. A3's ulock foundation can run alongside them. A4–A6 then fill process/VFS facilities without disturbing the recent cache work. A8–A10 build on socket/IP and Skywalk ownership; A11 remains specialized. Within Skywalk, establish configuration/controller/channel/ring and packet/memory contracts before deep datapath/queue and policy work; collect diagnostics and teardown evidence throughout rather than adding them only at the end.

This audit records all current chapters and the highest-value grouped additions, not every conceivable missing topic. Specialized leftovers include some NFS operations and RPCSEC_GSS, VFS trigger/graft paths, exhaustive kqueue filter variants, uncommon socket options/batch interfaces, and full protocol conformance. Source locations named only as future reading routes are not claimed as deeply reviewed. The missing APFS implementation, external pthread implementation, userspace policy/transport services, and hardware/firmware providers are limits on what this checkout alone can establish.

The result is a broad architecture with several strong implementation traces, plus a concrete backlog for facilities still introduced only briefly or not reconstructed at all. Neither retaining a chapter nor citing a large source file establishes complete implementation or branch coverage.
