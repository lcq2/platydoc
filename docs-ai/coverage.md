## What the guide represents

The guide was produced by inspecting the local `xnu-12377.121.6` tree. Three specialist agents explored the nine main subsystem areas in successive assignments; the coordinating review mapped the architecture, inspected build/observability/image-loading code, connected the paths, and checked navigation and consistency. No upstream web description was substituted for this checkout's implementation.

The IPC and ARM64 exception expansion assigned separate agents to namespace/right lifetimes, message transport, and hardware entry/return. Coordinating work connected kernel RPC, Mach exception delivery, and protected execution; independent reviews then checked the other authors' boundary descriptions. One official Arm reference supplies the architectural EL1↔EL2 contract, clearly separated from local XNU evidence and unavailable host/monitor implementations.

The VM expansion assigned separate agents to maps/faults, ARM64 pmap, and object/page/pager ownership. Coordinating work traced x86 pmap, end-to-end mapping examples, reclaim/compressor/swap, and kernel allocation. Independent reviews checked the other authors' mapping, fault-revalidation, pmap, reclaim, and allocator descriptions against the source. The resulting chapters distinguish common VM policy from the legacy ARM/PPL, SPTM, and x86 hardware backends.

The kernel-allocation expansion assigned separate agents to compiler type metadata and assignment policy, zone storage and specialized zones, and guarded kernel VM allocation. Coordinating work traced kalloc routing/free/realloc, IOKit/C++/BSD interfaces, restricted-page classification, and debugger/test entry points. Independent reviews checked other authors' allocation and release paths, type compatibility, cache accounting, address retention, and backend distinctions. The guide separates type placement from free-time validation, virtual-address reuse, physical backing, and protected mutation.

The protected-execution expansion assigned separate agents to SPTM, TXM, and Exclaves execution. Coordinating work traced Exclaves resource/task/port lifetimes, physical-page donation and sharing, service upcalls, and the combined entry/exit map. Independent reviews checked monitor call/resume paths, signature and frame ownership, hosted-scheduler and epoch-sync behavior, resource cleanup, and representative service handlers. The guides explicitly distinguish local executable code, stated external contracts, missing implementation, and comments that disagree with the current bodies.

The handbook-preparation expansion audited topic depth before adding material. Three agents first expanded runtime, BSD processes and networking, then continued into drivers, credentials/MAC/audit, CPU power lifecycle, IPC policy/vouchers/importance, and memorystatus/freezing. Coordinating work expanded VFS cache/reclaim, mount lifecycle, clustered writeback, SMR and cross-subsystem completion/failure. Original orientation guides remain available and link to the deeper chapters. The [audit](expansion-audit.md) records the selected gaps, implementation chapters and remaining limits; this phase produces Markdown and leaves HTML/SVG generation for user review.

The filesystem, scheduler, sleep and IOKit expansion added 21 implementation chapters. Separate agents traced namespace mutations, device/FIFO and stacked filesystems, NFS request handling, priority/quantum/RT/CPU eligibility, and hibernation image creation and restoration. IOKit assignments covered the object runtime, registry, notifications/arbitration, interrupts/commands, device power, CPU mappings and DriverKit dispatch/actions. Coordinating work connected boot and BSD root selection, system sleep/wake, shared queues, reporting and performance control. Independent reviews checked other authors' scheduler, image, sleep, queue, bootstrap and reporting paths; coordinating checks examined filesystem ownership and the new IOKit mechanisms. These are source-based chapters, with configuration and external-provider boundaries stated where they affect the path.

The file-cache/signature expansion added seven implementation chapters. Separate agents traced vnode allocation/reuse and authorization caching; UBC reads, read-ahead, mapping lifetime, truncation and buffer-cache ownership; and signature formats, transformations, attachment and cleanup. Coordinating work followed exec policy, executable-map association, page hashing, cached validation results and modification. Independent reviews checked other authors' vnode, file-data, buffer, executable-policy and page-validation paths; coordinating review checked signature parsing, publication, revalidation and monitor/supplement ownership. The resulting route distinguishes resident bytes, signature metadata, cached integrity results and executable mapping permission.

“Deep path review” means reading named structures, selected function bodies, adjacent invariants, callers/dispatch tables, and relevant cleanup paths. It does not mean every branch of a large file was audited. Each subsystem index provides a more specific sources-and-limits table.

The completed tree contains **225 Markdown pages, 190 Mermaid diagrams and 873 verbatim source excerpts**. Of those pages, 216 are explanatory guides/catalogs/build instructions and nine are coverage/audit/generated-navigation records. The explanatory guides directly cite **834 distinct files**; the whole tree cites **957**, including sources identified for future expansion in the audit reports and the HTML build entry point. These are citation counts, not reviewed-line or implementation-depth percentages.

The [local HTML builder](development/building-html.md) converts all Markdown pages into a searchable book with chapter navigation, an alphabetical concept/symbol index, native SVG diagrams, and highlighted source previews. The Markdown remains the editable source; HTML generation does not add source-review coverage. Build-time checks verify Markdown citations/excerpts and generated local links, heading/source anchors and SVG structure.

The AST and interface expansion adds 72 pages: two AST chapters, an entry-map overview, two Mach/machine-entry guides, 16 BSD catalog pages and 51 MIG catalog/index pages. It accounts for all 22 active AST bits; all 558 BSD numbers and 669 conditional alternatives, with 455 non-placeholder call descriptions; all 128 Mach trap slots; and all 49 subsystem-bearing MIG definition files. The seven MIG inspection profiles represent all 541 raw routine declaration sites, yielding 510 per-file routine slots and 23 always-reserved slots. Every routine slot has an authored mechanism or explicit implementation-boundary explanation. These overlapping/configuration-dependent counts are not the number of working APIs in one product.

The complete audit assessed the earlier 143-page baseline, including all 139 explanatory pages and four maintenance records. It added five audit pages and four implementation chapters: [pmap translations](subsystems/vm/pmap-translation-walkthroughs.md), [DMA segment generation](subsystems/drivers/dma-segment-walkthrough.md), [ARM64 exception assembly](subsystems/platform/arm64-assembly-walkthroughs.md), and [thread switching, entry and exit](subsystems/platform/arm64-context-switching.md). Those chapters add 19 diagrams and 38 excerpts. The [audit inventory](audits/inventory.json) preserves the earlier baseline of 653 directly cited files; its citation counts explicitly exclude audit-only references. The [Skywalk expansion program](audits/processes-vfs-networking.md#a12--p1-complete-skywalk-expansion-program) is a source-backed plan rather than completed whole-subsystem documentation.

The earlier handbook-preparation phase added 27 implementation chapters, the expansion audit and the TOC. The filesystem/scheduler/sleep/IOKit pass added another 21 chapters, 28 diagrams and 92 excerpts. The file-cache/signature pass added seven chapters, nine diagrams and 49 excerpts, with updated introductions and reading routes. The kernel-allocation overview and its six detailed chapters contain 10 diagrams and 55 excerpts. ## Implementation details checked against this snapshot

The guide deliberately calls out details that can differ from older XNU descriptions:

- Concrete native 4 KiB/16 KiB and forced-4-KiB pmap root selection, address indices and PTE examples were checked against local constants; PTE storage addresses and mapped output addresses are distinct.
- DMA descriptor offsets, UPL physical pages, mapped IOVAs and formatted segments have separate coordinates; output capacity, cursor state and errors do not form a transactional rollback contract.
- Kernel context switches return through saved kernel LR/SP, while user return restores the user PCB and executes `eret`; first dispatch and continuations manufacture/reset kernel execution state.
- ARM64 exception entry uses the active stack pointer temporarily as a PCB address; spill-option preservation across the PAC helper has an explicitly documented source/configuration uncertainty.
- Combined proc/task allocation and the shadow-proc handoff during exec.
- `thread_ro` associations and credential caches instead of assuming historical direct fields.
- B+tree map storage with entry/range locking and a map interlock; constrained VM submaps distinguished from hardware pmap nesting.
- System VM page size, map page size, and per-pmap translation granule kept separate through fault offsets and table walks.
- Slow fault revalidation checks object/offset and delayed-copy identity; entry-lock contention retries without deadlocking against a busy page.
- Legacy pmap locks and PTD counts distinguished from SPTM PV locks, epochs, monitor mapping counts, and temporary table pins.
- Mapping removal, TLB completion, reverse-map cleanup and physical reuse tracked as separate obligations.
- Current entry-list/kernel-buffer copies, wrapped-object memory entries, three-stage wiring and UPL activity holds traced through completion.
- Compressed PTE accounting markers distinguished from compressor-pager slots; dirty-page disconnect precedes reclaim, and swap submission has a separate completion lifetime.
- Direct memory-object pager operation dispatch in the inspected pager path.
- Fixed typed signature-prefix groups, finite zone budgets and variable signature-pair heap assignment distinguished from nominal C/C++ type identity.
- Shared EARLY allocation and compatible fixed frees distinguished from variable allocation's coarse heap-family checks.
- Central bitmap availability distinguished from released objects still held in magazines; zone GC can release physical backing while retaining VA.
- Non-DATA zone regions use sequestered bump allocation; ordinary DATA GC also retains chunk VA, while DATA destruction can return it.
- VM guard-object quarantine is an aggregate slot budget, not a per-address timer; fully empty chunks can return to map holes.
- RO source validation and mutation backends are configuration-specific; SPTM's visible aperture-write helpers are not the legacy PPL gateway.
- Private-data restriction mode is consulted by kmem's mapping selector; the zone selector uses DATA/RO/other region identity and must be described separately.
- The selected old/new reader-writer lock implementation rather than assuming the newer source file is the default.
- Direct message delivery distinguished from an explicit scheduler CPU handoff.
- Staged Mach message send/receive validation and phase-specific failure semantics.
- Packed `mach_msg2` header inputs, split kernel-message storage, and queue reservations distinguished from linked messages.
- Per-space urefs distinguished from kernel right instances and object references; receive migration and backup-port recovery distinguished from death.
- Exception-action send rights and kernel reply ports distinguished from ordinary user RPC ports; the Unix handler is a synchronous kobject destination in this snapshot.
- Persistent user saved state distinguished from transient kernel/interrupt stack frames; authenticated return values and AST continuations traced through assembly.
- Guest hypercalls, SPTM/GL resume selectors, legacy PPL fragments, and ordinary Mach exception messages kept as separate paths.
- SPTM mapping results, epoch drains, table pins, deferred TLB completion and frame retyping treated as distinct lifetime obligations.
- TXM uses a shared pool of boot-supplied stacks; interrupt resume uses the current thread's associated physical stack, and out-of-memory donation occurs after releasing that stack.
- Signature registration, verification, executable-region association and final mapping enforcement traced separately; TXM address-space teardown follows the current body despite a conflicting public header comment.
- Exclaves endpoint payloads and per-CPU scheduler buffers are separate protocols; scheduler responses can block/wake the host without completing its RPC.
- Exclaves context-cache capacity enforcement is disabled in this checkout, and scheduler Yield handoff remains TODO.
- Secure page donation preserves XNU VM bookkeeping; the free handler requires ownership to have returned already, while shared mapping separately validates frame types and service permissions.
- Exclaves resource send rights, numeric service IDs, SCIDs and task/conclave associations have separate identity and lifetime rules.
- Descriptor I/O references distinguished from shared open-file references, and vnode use count distinguished from I/O count and identity.
- Clutch hierarchy selection distinguished from a flat run queue; starvation windows do not guarantee a fixed per-thread execution quantum.
- Ordinary thread-call cancellation distinguished from `ONCE` cancellation and from waiting for active invocation completion.
- Process wait-result copyout failure distinguished from reaping; knote removal can precede event-result copyout.
- Name-cache SMR snapshots acquire a hold before leaving the reader section, then validate vnode identity when acquiring an I/O count.
- Clustered dirty-range removal distinguished from VM page cleanup; stream I/O accounting can complete before the main UPL commit/free work.
- Route object lifetime distinguished from route usability; interface object references, I/O references and data-movement drains are separate.
- User-client export removal, close callbacks, active-call finalization and surviving mappings are distinct lifetime transitions.
- Audit queue commit distinguished from worker output and durable storage; audit pipes have independent copy/drop behavior.
- CPU online publication distinguished from self-IPI readiness and caller-observed startup completion.
- RT policy validation and local conditional deadline selection distinguished from global admission guarantees; the `preemptible` policy field is explicitly ignored by this interface.
- Namespace operation success distinguished from subsequent attribute/security work: the generic create path does not undo every already completed filesystem mutation.
- Bind/null alias holds and vnode identity validation, FIFO socket-pair publication, and NFS duplicate-cache limits followed through their release and retry paths.
- Hibernation bitmap exclusion bits, image1 versus image2, restore scratch collisions, and post-restore VM bookkeeping treated as separate stages; legacy and SPTM entry paths kept distinct.
- OSObject collection-tagged references distinguished from ordinary references, and metaclass instance-presence propagation distinguished from counting every descendant object.
- Matching-notifier installation and snapshot selection share a lock, while callback replay and removal use separate retained owners and invocation drains.
- Registry property immutability, graph locking and iterator invalidation are separate mechanisms; copied containers do not imply cloned non-collection values.
- DriverKit `OSAction` retargeting and kernel event-source cleanup distinguished from externally implemented userspace dispatch and callback-drain contracts.
- CPU mapping aliases, named-entry mappings, descriptor preparation and device DMA addresses kept separate.
- Shared FIFO queues and overwriting circular queues have different publication, consumption, failure-progress and notification contracts.
- Device power requests, application response cookies, filesystem sync, platform sleep and wake classification have separate completion points; selected timeout and settle paths are qualified by the actual build guards and bodies.
- Reporter enable counts and sample output are separate from the performance controller's token/context and thread-group lifetimes.
- Vnode recycling and actual SMR storage deallocation distinguished from name-cache and file-page eviction; credential-cache TTL begins with the first accumulated action rather than every newly cached right.
- Demand cached reads retain their UPL through I/O wait and user copy; advisory reads delegate completion. Buffer-header identity, valid contents and storage ownership remain separate.
- Signature-parser acceptance, selected CodeDirectory identity, vnode policy generation, recorded mtime, process flags and VM checked/tainted/NX masks have different meanings and invalidation rules.
- Loader exact-length signature reads differ from fcntl's rounded allocation and short-read zero fill; a later output-copy error does not roll back a published attachment.
- Whole-page validation predicates differ from individual subpage bits; a checked hash mismatch still sets validated while reporting taint separately. Monitor association does not replace the eventual mapping check.
- SMR reader synchronization distinguished from queued callback completion; current sleepable-reader and clock implementations are described separately from stale surrounding comments.
- External function tables, generated interfaces, and missing filesystem/driver/policy implementations treated as real boundaries.

## Documentation checks

The dependency-free [link checker](tools/check_links.py) verifies:

1. Local Markdown link targets exist and remain inside the Platydoc project, with kernel references targeting its `xnu/` input.
2. `#L...` source references are within the target file's line count.
3. Markdown heading anchors resolve using the supported heading convention.
4. Fenced code blocks close and each document has a title.
5. Every Markdown guide is reachable from the main index.
6. Every marked source excerpt matches its cited local line range, including indentation, through the [excerpt checker](tools/check_excerpts.py).

The [TOC generator](tools/build_toc.py) lists all Markdown pages by reading area and their second-level headings. It rejects pages outside its classified directories. The [source-index generator](tools/build_source_index.py) maps cited source files back to chapters. These generated navigation pages are included in the ordinary link checks.

The [BSD catalog generator](tools/build_bsd_syscall_catalog.py) reconciles all master-table alternatives and authored descriptions/handler references; `--check` verifies its generated files. The [Mach trap generator](tools/build_mach_trap_catalog.py) verifies table metadata and generated rows with `--check`. The [MIG generator](tools/build_mig_catalog.py) preprocesses seven explicit declaration profiles with bounded `cpp` invocations, rejects uncovered raw routine sites or missing purposes/mechanisms, and records per-file ID slots plus local implementation evidence. It does not run MIG or claim to reconstruct generated wire layouts.

Run it from the Platydoc project root (outside `xnu/`):

```sh
python3 docs-ai/tools/check_links.py
```

These checks do not prove that every cited line establishes every sentence: the named symbol and surrounding implementation remain the authority. ## What was not executed
